## P1 — fix before or in 0.10.0 (integrator blockers)

### [P1] Sitemap ignores TSF noindex when toolkit serves sitemap

**Where:** `src/Modules/SitemapModule.php`, `src/Integrations/SeoFrameworkDetector.php`  
**Problem:** IndexNow uses TSF indexability; Sitemap only optional `dstk_sitemap_is_noindex`. When TSF is active but toolkit owns the sitemap, noindex posts can appear in XML.  
**Fix:** Shared `is_post_indexable_for_discovery()` for Sitemap + IndexNow + AiAgents.

### [P1] IndexNow silently drops pings when TSF is “present” but not queryable

**Where:** `SeoFrameworkDetector::is_post_indexable()` → false if TSF active but API not loaded  
**Problem:** Total silent IndexNow outage with TSF installed.  
**Fix:** Distinguish noindex vs unavailable; admin status; optional fail-open policy.

### [P1] Strict canonical equality blocks legitimate IndexNow URLs

**Where:** `SeoFrameworkDetector` vs `IndexNowModule` URL normalizers differ (trailing slash, encoding).  
**Fix:** One shared URL normalizer; reject only explicit noindex / external canonical.

### [P1] Rewrite flush hardcoded to hide-login + sitemap

**Where:** `src/Admin/SettingsPage.php` (sanitize/flush scheduling)  
**Problem:** AiAgents rewrites will stay dead after save until manual permalink flush.  
**Fix:** Rewrite settings fingerprint / module contract for flush.

### [P1] Missing tests: DisableComments (0.9.1 hardening), uninstall.php

**Why:** Security and uninstall claims unenforced by CI.  
**Fix:** Minimal unit coverage before growing the surface with AI Agents.

## P3 — polish

- REST `OPTIONS` always bypasses lockdown.
- Dummy recovery-mode query args change hide-login 404 fingerprint.
- IndexNow key lives in autoloaded `dstk_settings`.
- IndexNow manual-submit errors flash via query string.
- `ModuleInterface` is register-only (no onDisable lifecycle).
- `SettingsPage.php` ~830 lines — AI tab should be `Admin/AiAgentsPage.php`.

## What is solid (keep)

1. Modular boot, masters default off, no Composer runtime on client sites.  
2. Settings sanitize (endpoint allowlist, trusted caps, `_submitted` checkboxes).  
3. `GitHubReleaseUpdater` — digest, size, package structure; not GitHub source ZIP.  
4. `RewriteManager` — flush before clear pending (0.9.1).  
5. `uninstall.php` — options, IndexNow state, sitemap transients, multisite `network_id`.  
6. CI PHP 8.1/8.3/8.4 + release tag must match plugin version.  
7. Unit suite strength on HideLogin, REST, Sitemap, UpdateControls, Settings, updater.

## AI Agents integration risks (carry into plan)

- Multiple `rewrite top` owners: reserved names + path-based serve (Sitemap pattern).  
- `robots_txt` ~20: AI discovery lines only; never duplicate `Sitemap:`.  
- REST lockdown does not gate public AI rewrites (document).  
- Respect `blog_public` when advertising discovery.  
- Do not further bloat `SettingsPage`; use dedicated AI admin page.

## Residual risks (accepted for 0.9.1)

1. Hide-login is obscurity, not multi-factor auth.  
2. Auto-update trust bound to GitHub account without cosign.  
3. Unit suite without full WordPress runtime can false-green on hook order.  
4. No P0 found in multi-pass review.
